## Frontend Contract Audit

There is no backend service, HTTP API, socket layer, auth, or persistence contract in the current prototype. The frontend contract is the local engine facade and adapter projection:

- `createDuel`, command helpers, and reducer-compatible actions in `src/engine/duel.ts` and `src/gameLogic.ts`.
- Core command and result types in `src/engine/commands.ts`, `src/engine/result.ts`, `src/engine/errors.ts`, and `src/engine/events.ts`.
- Serialized core state in `src/engine/core/state.ts` and `src/engine/serialization.ts`.
- UI-facing selectors in `src/engine/adapters/frontendAdapter.ts` and `src/engine/adapters/viewSelectors.ts`.

Contract preservation rules:

- Preserve existing command names and payload shapes unless React components and adapter tests are updated together.
- Preserve hidden opponent hand, deck, and face-down field information in adapter projections.
- Preserve stable card identity as passcode/cardId, not name.
- Keep runtime card text as display data only; effects must come from scripts/templates/base rules.
- Keep unsupported effects explicit and non-mutating until implemented.

Existing contract tests include `frontendAdapter.test.ts`, `frontendCoreRouting.test.ts`, `goldenFrontendSmoke.test.ts`, `noRuntimeTextParsing.test.ts`, and coverage/deck gate tests.

## Card Data Schema

Canonical card identity is `passcode`, preserving it as a string. `id` currently matches `passcode` for local records and is validated as identity data, but passcode remains the primary engine key.

Source index is the zero-based `cards.json` array offset. Card Task ID is derived from source index as `C-${sourceIndex + 1}` padded to four digits.

GOAT pool and banlist data come from:

- `legality.goat_world_pool`
- `legality.restriction`
- `legality.max_copies`

Card text is read and recorded in the matrix for review, but is not parsed at runtime for behavior.

## Matrix And Validators

The implementation matrix is generated by:

```bash
npm run coverage:matrix
```

Validators:

- `npm run coverage:validate`: development mode; allows temporary `goatUnsupported` but reports counts and samples.
- `npm run coverage:final`: final mode; fails unless `goatUnsupported = 0`.
- `npm run coverage:report`: prints counts and unsupported samples for milestone tracking.

The validator checks:

- every `cards.json` row has one manifest status;
- every Card Task heading maps to exactly one source row;
- every matrix row maps to exactly one source row and Card Task;
- source index, card ID, passcode, name, GOAT pool, restriction, and matrix status stay consistent;
- non-GOAT rows are marked `notInGoatPool`;
- restriction/max copy pairs are internally consistent.

Shard rules:

- A Card Task ID and passcode may be owned by only one active shard.
- A shard may edit matrix rows, scripts, tests, and review notes for its owned cards.
- A shard must stop and merge-gate if it needs shared engine primitives, shared templates, validator changes, or frontend contract changes.
- Before merge, a shard runs targeted card/template tests, affected interaction tests, `npm run coverage:validate`, and `npm run typecheck`.
- After merge, run global matrix/backlog validation and affected regressions. Run full `npm test` and `npm run build` at shared-surface, milestone, and final gates.
- Merge summaries list completed Card Task IDs, passcodes, scripts/templates changed, tests changed, validators run, and deferred full-suite gates.

## Tiered Test Strategy

Card-local validation:

- matrix row identity/status;
- script/template registration when status is `goatTemplate`, `goatCustom`, or `goatForbiddenButScripted`;
- card-specific or exact template tests;
- affected interaction tests for timing, targeting, Damage Step, priority, equip, control, replacement/prevention, triggers, search/reveal, and privacy.

Template-family validation:

- run the template test file and representative production card tests whenever a shared template changes.

Shard-local validation:

- all card-local checks for the shard;
- affected interaction regressions;
- `npm run coverage:validate`;
- `npm run typecheck`.

Shared-surface validation:

- full targeted regression set for the affected engine/rule/template surface;
- `npm run coverage:validate`;
- `npm run typecheck`;
- `npm test` when reducers, adapters, validators, or shared templates change.

Final validation:

```bash
npm run coverage:final
npm run typecheck
npm test
npm run build
```
